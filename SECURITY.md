# Política de segurança

## Versões suportadas

Durante a fase `0.x`, somente a versão mais recente no branch `main` recebe correções. A política será revista antes de `1.0.0`.

## Reporte responsável

Não publique vulnerabilidades, tokens, dados pessoais ou exploits em issues públicas. Use o recurso **Report a vulnerability** do GitHub Security quando habilitado ou contate privadamente o responsável pelo repositório.

Inclua componente, versão, impacto, reprodução mínima e mitigação sugerida. Não acesse dados de terceiros nem execute testes destrutivos.

## Compromissos

- confirmar recebimento antes de divulgar detalhes;
- classificar impacto e alcance;
- corrigir com teste de regressão;
- revogar credenciais expostas imediatamente;
- documentar versão afetada e atualização segura.

## Segredos e dados

O repositório não armazena credenciais. A CLI não publica dados externamente. Logs e erros devem conter identificadores técnicos, nunca documentos integrais, tokens ou dados pessoais desnecessários.
